## Verified baseline and design

The app is Vue/FastAPI with one WAL SQLite catalog (`aicollector.db`).
`audio_version_store.migrate()` is an additive/idempotent migration invoked by
`db.get_db()`. Versions retain originals, own captured input files and persist
apply receipts; exports own supervised FFmpeg workers and adjacent hash-bound
`ExportProvenance` JSON/text manifests. Those manifests are informational and
do not currently enforce a source graph or legal permission.

Singing preparation has reviewed segments, optional cleanup, pYIN occupancy,
explicit singer confirmation, a 60-minute selection ceiling and separate trial
uploads. Artifacts retain baseline hashes, selection fingerprints, isolated runs
and full-state resume checkpoints. Application currently resolves the active
model inside the worker and always separates the input song into four stems.
Consent, artist range, immutable usage evidence and royalty accounting are absent.
The app has no authentication. A local operator declaration is not an authenticated
identity, legal consent, or automated singer/copyright detection.

create a second source of truth. Historical assets stay unknown. The new workflow

2. **Consent/profile boundary.** Add typed artist profiles and append-only versioned
   permission evidence in `artist_contracts.py`/`artists.py`, plus local API routes.
   Associate a singing voice with one artist without rewriting historical outputs.
   Require evidence reference, operator declaration, scopes, dates and non-revoked
   authorization for new registered-artist training/conversion/comparison/export.
   Revocation must not silently disappear when a caller uses a legacy endpoint.
   Test missing/expired/revoked scope, stale versions and persistence.
3. **Durable source graph.** Add bounded versioned contracts and additive SQLite

4. **Independent guide pipeline.** Add a separately bounded upload route for isolated
   human guide + accompaniment. Reuse upload validation, owned apply jobs, phase-safe
   mono preprocessing, Seed-VC inference, level matching, limiter and immutable
   version publication. Bypass separation for isolated guides. Snapshot model ID,
   checkpoint/config/reference hashes at submission, reject changes before inference
   and publication, record observable auxiliary hashes and unverified dependencies.
   Persist source-to-render binding and graph before reporting completion. Test
   generated/Suno ancestry, no guide, unknown license, source/model changes,
   cancellation, worker failures, reload and successful CPU-fixture mixed output.
5. **Export/release review.** Extend `ExportProvenance` with an optional versioned
   production snapshot; retain compatibility with v1 manifests. Strict exports
   revalidate their exact audio version's lineage and permission. Human composition,
   master and voice-rights attestations are separate events. Unknown engine/weight/
   auxiliary permission prevents commercial clearance. Original and non-strict
   versions cannot inherit approval from a track label. Test retries and changed
   sources/permissions during export.
6. **Focused singing UX.** Add a reusable artist panel to SingingVoiceWorkspace using
   generated contract decoders, existing input/button/player patterns and English
   localization keys. Present profile -> permission -> recording script/QC -> pinned
   versions/listening -> clean guide production/release blockers. Use async generation

   target is a heuristic 45 minutes (10/10/8/7/7/3); begin with 15–30, cap selection

   preprocessing at 44.1 kHz cannot recover detail. No performance-control fiction.
7. **Retention/deletion.** Freeze registered-artist new use, drain owned workers,
   inventory recordings/checkpoints/trials/versions/exports/references/external caches
   and declared backups, and reconcile interrupted deletion. Never claim inaccessible
   backup/third-party erasure. Persist hash-bound receipts with completed/pending/
   external items and errors. Preserve release conflicts for explicit operator review.
   Do not delete real user data during implementation. Test in temporary libraries.
8. **Range, usage and accounting.** Confirm comfortable/extended ranges explicitly;

   silently transposing. Keep hash-chained model-use records separate from configurable

   No default royalty rate and no revenue inferred from jobs. Accountant/legal review

9. **Research and pilot.** Disabled-by-default synthesis research only; evaluate exact

   Keep a reproducible fixture pilot and measurement template; real Gladys held-out
   four-passage listening tests and hardware throughput remain unverified until run
   with authorized material. No GPU benchmark is inferred from mocked tests.

## Migration and recovery gates

New catalog tables are additive, idempotent and foreign-key constrained; no legacy
row reclassification or destructive backfill. Relative owned paths migrate with
`files/`, `voices/` and existing catalog backup/WAL handling. Test opening an old
catalog twice and copied-library relocation. Rollback procedure: stop the app,
take a consistent SQLite backup and copy media; revert application code, leaving
new tables unused. Never drop evidence tables or delete media as rollback.
Hash-chain evidence detects alteration with a retained head/receipt; it is not a
signature, authenticated actor proof, or protection against an administrator who
replaces the entire database and all receipts. Originals remain immutable.

Source evidence approvals now bind the exact declaration revision under a write
transaction. Amendments append history and require fresh review; stale approvals
cannot clear them. Original source identity/provider/role/filename remain immutable.
Duplicate valid uploads reuse the recorded identity and remove only their redundant
owned copy. Re-uploading a missing original creates a new unreviewed identity;
historical graphs retain their missing-file blocker.

Registered recording acceptance is drained on cancellation. QC-committed originals
survive metadata failure/revocation; per-file publication retains partial batches.
A later successful upload reconciles byte-verified orphan QC originals. Copy-name
races never delete another uploader's winning file. Shared export records use a
consistent 8 MiB read/write cap and reject oversized writes atomically.

Retained failed/cancelled conversion bytes are recognized as generated on re-upload;
job outcome never changes origin. Retention execution reserves a terminal receipt
slot before deletion and reports capacity failures without removing files.

Concurrent upload stress exposed a shared SQLite statement-cache read defect on
the installed CPython 3.12 runtime. The shared connection now disables statement
caching, while existing dedicated write transactions remain intact. Tests drain
all sibling uploads before closing their catalog. A reentrant startup lock also
prevents cold workers from receiving a partly migrated connection; both core and
component initialization failures discard the partial connection before retry.
These are catalog correctness fixes, not a replacement database architecture.

Migrations add 21 tables including schema markers; no old row backfill or media
deletion occurs at migration. Parent/review/profile/accounting links use foreign
keys; run and usage envelopes remain validated typed JSON. Startup component
commits are recoverable/idempotent, rather than one global migration transaction.

The next production slice needs an actual signed singer agreement, approved exact
runtime dependencies and consented held-out material: four diverse listening
passages and hardware measurements using the pinned chain. No synthesis adapter
or enable flag is implemented; research remains an evidence-only blocked path.
Other known limits are listed in ACCEPTANCE_REPORT, including API-only release/
adjustment entry and the absent destination-territory selector/authenticated roles.
