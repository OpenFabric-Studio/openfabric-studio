# Regional preset candidates

This catalog records the 24 preset proposals and 15 rhythm proposals in the supplied *OpenFabric Studio Music Features Research Report v1.0*, 16 October 2026, §§6.2–6.4 (printed pages 18–22). It does not establish musician review, asset ownership, listening quality, or complete implementation of the traditions named by the report. Every definition is explicitly `unreviewed`. Traditional, fusion and modern pop describe proposed arrangement categories.

The four app-owned JSON files contain bounded declarative data. No scripts, filesystem paths, sample downloads or publisher URLs execute from this catalog. Scales are report-scoped candidates: Chinese rotations, Japanese named variants, Korean equal-tempered approximations and Indian pitch collections retain these qualifications in their notes. In particular, the Kalyan collection does not implement Yaman's phrases, ascent/descent or ornaments. The synthetic five- and seven-equal-division tables are labelled experiments; no regional preset selects them.

Source-specific tuning is intentionally absent for the Javanese/Balinese ensembles, Thai instrument set and khaen mode. This is a material difference, not missing arithmetic. Ableton's artist-authored [Sundanese tuning reference](https://tuning.ableton.com/sundanese-gamelan/pelog-7-tones/) documents two particular instrument sets with different reference pitches. It concerns those Sundanese examples; it does not verify this catalog's Javanese or Balinese candidates. The Met's [individual slendro saron record](https://www.metmuseum.org/art/collection/search/501374) supports identifying that particular instrument and its five-tone tuning, without supplying cents for a proposed pack. Neither source licenses or measures a sample pack for this app.

`catalog(manifests=...)` reports availability only for the supplied kit manifests. Empty/default installations therefore show `pack_missing`, even for arrangements expressible on the grid. An imported compatible kit must supply exact instrument IDs and roles; each sample region needs a matching SHA-256 identity, a declared redistribution permission and a hashed license-file observation. This is a declaration/evidence check, not an independent determination of a publisher's rights. The existing renderer remains responsible for validating and loading the actual files. A generic oscillator, harp or unrelated recording is never silently substituted under a regional instrument's name.

`compile_preset(request, manifest=...)` is pure: it performs no audio loading, writes, installations or persistence. It returns a strict `BeatDocument` validated through the common event compiler, plus the preset hash and explicit warnings. The request selects an existing kit, document ID, seed, optional quarter-note BPM and tonic. A stable per-part seed selects a rotation of the declared candidate motif within its candidate pitch collection; it does not simulate a musician's phrasing. All events stay in the common rational grid. Sparse generic accents are experimental sketches, not reviewed transcriptions of luogu, kuchi-shoga, jangdan, chaal or theka. The 16-beat teentaal grouping and sam/khali labels are report-scoped metadata; no unrecorded tabla stroke is fabricated.

With complete compatible fixture manifests, 16 proposals compile; the remaining six need measured tuning and two need timing features the common document cannot express (Lion Dance acceleration and Gayageum Sanjo cycle progression). Guzheng Dawn and Kyoto Koto explicitly warn that their fixed grid approximates the proposed free phrasing. Peking Opera Drums does not invent a jinghu part without a declared pitch collection. The compiler supplies empty editor lanes to satisfy the common editor's eight-lane minimum, reusing admitted instrument identities rather than inventing more assets.

The current catalog's runtime availability is **not** demonstrated by these fixture tests. No regional sample pack or musician approval was added. Phase 04 cannot be called asset-complete or musically reviewed on the strength of JSON and deterministic tests. See [review scope](review-scope.md) and [asset research](asset-sources.md).

Record the reviewed preset hash, kit manifest hash, exact rendered hashes, reviewer scope and requested revisions. A changed definition, tuning or pack invalidates that review. No review identities or approvals are invented here.
