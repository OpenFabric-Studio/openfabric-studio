# Optional offline CPU beat analysis

Recorded 2026-10-17. `MusicAnalysisRequest.profile="music-beats-v1"` explicitly selects the optional beat/downbeat path; the default `music-v1` retains the existing model-free analysis. Both use the same source resolver, snapshots, SQLite jobs/results/corrections, CPU serialization, supervisor and cancellation/recovery owner. There is no second analysis queue or model server, and analysis never installs dependencies or downloads a checkpoint.

## Source and model identity

The reviewed package is upstream [beat_this v1.1.0](https://github.com/CPJKU/beat_this/tree/ad7974846029835307ba19a3d5cefbf40b243041), commit `ad7974846029835307ba19a3d5cefbf40b243041`. The exact [inference source](https://github.com/CPJKU/beat_this/blob/ad7974846029835307ba19a3d5cefbf40b243041/beat_this/inference.py) exposes `Audio2Beats(checkpoint_path, device="cpu", float16=False, dbn=False)`. The app uses that CPU/float32/minimal-postprocessor combination, not madmom's optional DBN. The package's published wheel is 40,060 bytes, with PyPI metadata SHA-256 `3f2b2d1e027c6dac380bf80c71555e3c28a4036a7f1af20129a945915a72a645`; the optional requirements pin its exact URL/hash. The installed package's fifteen Python files have aggregate SHA-256 `900e9a9bcc1ceb40a249df5a4b8bfaec48e2fa38553388952719842a8be51a34`. The six inference-path source files were independently compared against the pinned upstream commit and matched.

The [publisher's checkpoint endpoint](https://cloud.cp.jku.at/public.php/dav/files/7ik4RrBKTS273gp/small0.ckpt) reported `small0.ckpt` at 8,451,101 bytes and `OC-Checksum: SHA1:77a7ef5c21f628578f2b259ac29d2d680412efcc`. An explicitly authorized temporary download was limited to 12 MiB, matched that size/SHA-1, and produced observed SHA-256 `6074be2c4d490c5f6101fcc374a1ec72ae93456e23bb6019783b849f5dc7d47b`. Managed model acquisition uses this observed SHA-256. It is not described as a publisher-issued SHA-256 or signed checksum.

The [pinned README](https://github.com/CPJKU/beat_this/blob/ad7974846029835307ba19a3d5cefbf40b243041/README.md#license) declares MIT for code and published weights, while warning that training recordings have separate rights. The reviewed README SHA-256 is `c9a2f5d91fe561be815122d77496d6e774cb98744d8128693d25b09f5202959d`; [LICENSE](https://github.com/CPJKU/beat_this/blob/ad7974846029835307ba19a3d5cefbf40b243041/LICENSE) SHA-256 is `909ab6549794a18e9bb243aacfadda4a5f308436fc2846f350755c53c4f06ae1`. ## Setup, boundaries and recovery

The existing module installer owns `music_beats` under its managed `engines/MusicBeats` directory. It installs a separate Python 3.12 environment with pinned beat-this 1.1.0, torch/torchaudio 2.6.0, NumPy 2.2.6, einops 0.8.1, rotary-embedding-torch 0.8.9, soxr 0.5.0.post1 and Pydantic 2.13.5. Non-macOS setup selects the official PyTorch CPU index. This is an implementation path, not Linux/Windows native qualification. The controlled macOS proof environment occupied about 498 MB including its small checkpoint and installation logs; dependency setup requires additional free-space headroom and is not advertised as an exact cross-platform size forecast.

Dependency-only setup leaves weights unavailable. Selecting model download in setup acquires only the exact small0 artifact. Readiness checks bounded local metadata, selected source hashes, interpreter identity and checkpoint bytes; it does not import PyTorch or start inference. Pending install ownership is recorded before dependency work, then refreshed synchronously when the completed dependency marker replaces the pending marker, before the cancellable model download. Modified or foreign installations are preserved. Tests cover cancellation at this transition and successful resumed installation through the real installer dispatch.

Upstream's missing-local-file branch can download a checkpoint by name. The dedicated app worker replaces its loader with a retained-byte, `torch.load(..., map_location="cpu", weights_only=True)` path. It accepts only the exact retained checkpoint, disables network connection/lookup requests through a child-only audit hook, forces CPU and one Torch compute/interoperation thread, and never selects the optional DBN. Restricted deserialization is not a general execution sandbox. The worker receives no public filesystem path, URL, device choice or arbitrary native option.

Decoded input is finite float32 at 22.05 kHz, one/two channels, at most 120 seconds/2,646,000 frames per invocation, preserving finite source overshoot up to the existing amplitude bound. It is validated before constructing the model. Stereo selects the channel with greatest window energy; it does not average antiphase channels into silence. This explicit preprocessing participates in configuration identity. Only one PCM window is loaded at a time; upstream inference internally splits its spectrogram into bounded model chunks. These input/allocation bounds do not constitute a measured maximum RSS guarantee for every supported platform.

Long sources reuse the existing ten-second-overlap decode loop. Central intervals retain source-time offsets, deduplicate boundary events within one model frame and leave explicit `window_boundary_uncertain`/`analysis_partial` warnings. The app does not claim phase-consistent full-song downbeat tracking across independent windows. A stable grid with at least eight events may yield a descriptive median-interval BPM; irregular or short grids leave tempo unknown. Confidence is always null, half/double ambiguity remains explicit, and meter remains unknown. No non-4/4 or cultural interpretation is inferred.

The job retains `beat-checkpoint.ckpt` in its private analysis workspace for durable retry; previews account for its bytes separately from the retained source. Successful windows remove their `beats-input.f32`, `beats-request.json` and `beats-result.json`. Failed/uncertain child exits retain those private inputs for owner quarantine. Verified retries can replace quiescent window files; unknown descendants remain owned by the existing analysis supervisor. The raw result's weights hash, beat engine configuration hash and declaration IDs must match the captured recipe before publication or cache reuse. Corrections remain per-result and separate from raw estimates.

## Actual macOS CPU observations

All audio below was generated synthetic material in a separate temporary library; no user audio, GPU, live runtime or live module setting was used. The environment/checkpoint acquisition above was explicitly authorized. Unit tests do not install dependencies, load checkpoints or download models.

| Actual check | Observation |
| --- | --- |
| 20-second accented 120 BPM antiphase stereo clicks, direct guarded worker | Exit 0; 5.107 seconds including cold Python/import; maximum child RSS 411,926,528 bytes. All 40 reference clicks had a prediction within 70 ms, but the model returned 41 beats and an extra final downbeat. This was not a perfect result. |
| 130-second source through the full owned analysis pipeline, including FFmpeg measurement, 120-/20-second model windows and SQLite publication | Completed in 11.273 seconds; all 260 reference clicks matched within 70 ms, with 261 predictions. Exact 2,866,500 source frames retained. Tempo summary 120 BPM, confidence null, meter unknown, boundary warnings present. Original hash unchanged; owner idle after completion/shutdown. |
| Cancel while the nested optional model child was active | Returned cancelled in about 0.00685 seconds; worker identity/ownership cleared after drain; retained checkpoint remained. |
| Retry that cancelled job while its temporary global checkpoint was deliberately unavailable | Completed in 10.915 seconds from its retained checkpoint, with the same exact source frame count and conservative tempo/meter metadata. Original hash unchanged; shutdown idle. |
| Browser-generated eight-second procedural beat/synthetic-song mix | The native tracker returned an event exactly at 8.0 seconds, exposing a half-open interval boundary defect. After regression/fix, explicit retry of the same preserved job completed in 2.084 seconds: eight beats, four downbeats, 60 BPM with half/double ambiguity, null confidence and unknown meter. Results survived a backend restart. The authored grid was 120 BPM; do not present this as perfect tempo detection. |

Elapsed times are observations from these fixtures, including concurrent development activity; they are not production latency targets. The final private proof tree was about 609 MB, below the authorized 1 GiB cap. No full two-hour runtime, real-song accuracy, held-out dataset benchmark, native non-macOS inference or musician listening study was performed. A successful process and a plausible BPM do not establish musical correctness. Manual corrections and the model-free baseline remain necessary.

Focused tests additionally reject missing/changed/symlinked runtime artifacts, malformed/nonfinite/oversized PCM, detached or unordered beat arrays, foreign configuration/weight evidence, uncertain child cleanup, cross-window gaps/overlap and silent or unstable tempo claims. Existing analysis tests continue to exercise source mutation, ownership/drain, recovery, cache/correction isolation, bounded disk/decode and route validation.


The endpoint fix validates the full native sequence first, then omits events at or beyond the end only within one 50 Hz model frame (20 ms plus numeric tolerance). It does not move/clamp events into the window. More distant outliers, negative/nonfinite values, ordering errors and duplicates still fail validation. A separate actual worker run on a private copy of the previously failed eight-second input also exited 0; its input/configuration hashes matched. The browser proof is `/tmp/openfabric-cpu-analysis-browser-proof.json`.
