# Generator history, presets and reference preparation

Open **History & presets** in either generator or in **Settings → Generation history and presets**. History stores a snapshot for each completed generated track, including lyrics and generator settings. The default is the newest **100** entries across both engines. Settings accepts a limit from **1 to 10,000**. Reducing it prunes metadata immediately; increasing it cannot restore entries already pruned. Audio files, track favourites and saved presets are independent.

Use a history entry to refill its generator or save it as a named preset. Reuse keeps the generated lyrics and the selected result's actual seed when available, even if the request originally used a random seed or generated several variants. An ACE simple request with generated lyrics opens in Custom mode so those lyrics can be reused. The stored input snapshot remains unchanged. Presets are permanent independent snapshots: rename, edit, duplicate or delete them in the manager. A preset survives history pruning and track deletion. Existing browser presets are imported idempotently; the browser copy remains until the backend has acknowledged it. Concurrent edits use revisions, so another window cannot silently overwrite a newer preset.

A snapshot can retain the name of a reference file, a preparation result and a LoRA selection, but it cannot recreate a browser upload or guarantee an installed model remains available. Review the restored fields and reattach or reselect anything marked as required. History is a record of the inputs, not a promise of bit-identical output across engine or model updates.

YuE generation is owned by the backend. Closing the generator page does not abandon a successful output. Queued cancellation removes queued work; cancellation during a native call stops and restarts its owned server before another native job is admitted. A failed stop holds the reservation and reports recovery is required. Completed WAV masters and generated ABC scores are retained, including recovery after interrupted catalog publication.

Elapsed time is available with the stock native engine. Detailed native phase counts require a reproducible patched source build; see [native patch instructions](../external/patches/README.md). The build helper produces a binary identity manifest, and `YUE2_SERVER_BIN` opts into that validated binary. Planning and semantic token limits are not percentages. An ETA is shown only for a countable phase after measurements exist, and it describes that phase rather than the entire song.

Stem MP3 exports use the exact separated source and the shared encoding profile from Settings. Existing WAV downloads remain available. Export jobs can be cancelled or retried and are drained before stems or their track are removed. Changing MP3 settings affects new exports; a retry keeps its captured original profile.

Reference preparation is optional. It can import a supported provider URL or prepare a track already in the library, with selected lyric, separation and melody stages. Review the result before applying it to a generator. Missing tools are shown as capabilities, and each stage reports its result separately. The original source container is retained unchanged; requested native or Whisper preparation uses a temporary PCM WAV. The URL importer accepts supported public provider endpoints and rejects private-network addresses; it is not a general-purpose URL downloader. See [reference setup and supported text tools](reference-preparation.md) for the pinned optional dependencies and the supported ABC subset.

Completion notifications are opt-in in Settings. Browser notifications need permission; the desktop bridge uses the operating system. Notifications follow durable track saving and requested voice conversion, with unread state to find completed work later.
