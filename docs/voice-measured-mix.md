# Measured voice-conversion mixing

Voice application has an explicit optional `mix` setting. Omitting it preserves the legacy Seed-VC conversion, RMS gain and limiter path. Supplying `VoiceMixSettings` keeps the existing ApplyJob, cancellation, GPU lease, model authorization, audio-version publication and recovery ownership, then uses the shared CPU DSP helpers for measured vocal gain/effects and the final mix. It adds no separate job queue or database tables.

The opt-in is available as `mix` on JSON voice-apply and audio-version creation requests. The existing multipart `/api/voices/replace` endpoint accepts optional `mix` JSON, bounded to 16 KiB and validated before library writes. `mix: {}` selects measured original-vocal level matching with processing and master normalization off. Manual gain, bounded EQ/compression and the existing loudness profiles are explicit choices. There is no hidden limiter or target-success claim. Short/silent/unmeasurable sources retain unknown loudness and warnings rather than an invented gain.

Responses expose `mix_settings` during work and a completed `mix: VoiceMixReport` afterward. Each report binds the exact source version/hash, selected model revision and observed checkpoint/configuration/reference/engine-source hashes, shared transform/mix requests and measured results, actual applied gain, residual level difference, warnings and retained artifact identities. Auxiliary dependency inventory and bitwise determinism remain explicitly unverified in `VoiceModelSnapshot`.

The source version and observed model are pinned independently of the active voice selection. Admission captures file identities without hashing large checkpoints on the event loop. Owned hashing verifies them before inference and publication. A version's saved model identity and settings cannot silently change during retry; create another version for different choices. Completed retained renders with matching source/settings/model can finish interrupted catalog publication without separation or conversion again.

Retained original vocal, converted dry vocal, backing stems, processed vocal and master live under the owning immutable version directory, outside the temporary apply workspace. Each attempt has a fresh UUID directory and typed report. The current report is atomically published only after the full CPU mix has been validated. Existing evidence registration resolves the authoritative catalog version itself and records an app-workflow reference without creating a user rights declaration. Derived assets keep explicit parents. Existing classification/evidence is preserved; unknown inputs and general replacement do not acquire strict-production eligibility.

Artifact playback uses `/api/tracks/{track_id}/versions/{version_id}/mix/artifacts/{artifact_id}`. The backend checks the track/version association, contained UUID manifest path and actual artifact hash. Public reports expose app-relative URLs and filenames, never private paths or worker receipts. Raw model errors remain in backend logs. If retained metadata is missing or corrupt, the audio version remains independently available and its measured report is unavailable; it must not receive a measured-quality claim from absent diagnostics.

The strict isolated-guide artist-production path rejects these general settings and retains its existing validation and rendering policy. Prepared/hybrid alignment, RVC, remix editing, explicit artifact cleanup and listening-based quality approval belong to the subsequent replacement-plan workflow. This opt-in does not add high-quality separation, cleanup, formant correction or automatic legal clearance. Its separator/converter behavior remains the current owned legacy implementation.

Verification uses temporary catalogs and generated audio with mocked model inference. Real CPU tests establish measured +6.02 dB matching of a half-amplitude synthetic vocal, exact final frame counts, retained artifact playback after reload, immutable source preservation, malformed-audio rejection, low-disk refusal, model mutation rejection, cancellation/process drain, fixed retry settings/model identity and completed-render reuse without another model call. Existing voice/version/strict-production/lifecycle regressions are required alongside these tests. These fixtures establish software behavior; they do not establish real singing quality or GPU performance.
