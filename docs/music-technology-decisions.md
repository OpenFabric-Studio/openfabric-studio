# Music technology decisions

Recorded 2026-10-17 against the music-feature implementation worktree. This is a disposition of the [optional technology catalog](superpowers/plans/2026-10-17-music-08-optional-technology.md), not a claim that every proposed experiment ran. The catalog transcribes report candidates; its popularity, compatibility and license descriptions are not installation or rights evidence.

**Adopt** below means use for the stated, bounded capability. **Preserve** means retain the existing integration without expanding its claims. **Investigate** means source/runtime evidence is still being gathered. **Defer** means no additional dependency, model, selector or engine owner is justified yet. These decisions authorize no download or live inference.

## Evidence needed before expanding a decision

Use the plan's experiment checklist for a selected candidate: a measurable question, exact source/dependency/model identities, declaration evidence, isolated setup and disk forecast, owned worker/cancellation/recovery tests, and a measured comparison against the current baseline. Keep original audio, dry outputs and unsuccessful experiments reviewable. Record actual hardware, runtime and fixture scope; do not generalize synthetic CPU tests to GPU inference or musical listening quality.

The current regional workflow has no FAD/CLAP/instrument-classifier result, trained regional improvement or recruited musician panel. Candidate presets and report recognition targets remain unverified. Saving a review or completing a job does not change an unknown permission or `quality_status="unverified"` into approval.

This decision record was initially produced from repository code, pinned declarations and existing validation reports. A subsequent explicitly authorized, bounded temporary beat_this CPU experiment is recorded above and in its validation record. No live library or live runtime was processed or changed; deferred candidates were not installed or benchmarked.
